# El artefacto del contrato · `contracts/ope/`

**Carpeta**: `005-la-base-de-ope` · **Fecha**: 2026-10-08

Lo que el frontend espera encontrar en `contracts/ope/` después de `npm run contract:sync`, y por lo
tanto **lo que la feature 040 de OPE-Backend tiene que emitir en `generated/contract/`**. Es la forma
que `TAN-7` dice que el frontend publica: el backend emite, el frontend declara qué forma tiene lo
emitido y verifica que coincida.

Mientras 040 no exista, `scripts/contract-sync.mjs` produce `capabilities.*` e `identity.json` desde
el bundle, con cabecera que lo dice. El resto se copia tal cual del backend.

## Los archivos

| archivo | de dónde sale | quién lo lee |
|---|---|---|
| `openapi.yaml` | `contracts/dist/openapi.yaml` del backend, sin tocar | `conformity` (su `sha256`); una persona |
| `api.d.ts` | `generated/api.d.ts` del backend (openapi-typescript) | `openapi-fetch` en `apps/*/src/api/ope/`, y `conformity` |
| `problem-types.d.ts` | `generated/problem-types.d.ts` del backend | `@ope/core` (`ProblemSlug`) |
| `capabilities.js` + `capabilities.d.ts` | `generated/contract/capabilities.*` (040); interino: emitido acá | `operation()`, `conformity`, la sesión falsa |
| `identity.json` | `generated/contract/identity.json` (040); interino: emitido acá | `conformity`, el `README.md` |
| `README.md` | lo escribe `contract-sync` | una persona: de qué commit del backend salió, y cuándo |

Todos **versionados**. `.gitattributes` los marca `linguist-generated`. Biome y Vitest los excluyen.

## `capabilities.d.ts`

```ts
// GENERATED by <script> from contracts/dist/openapi.yaml — DO NOT EDIT BY HAND.
// Regenerate with: npm run contract:types   (backend)  ·  npm run contract:sync   (frontend)

/** The contract this module was derived from. */
export declare const CONTRACT: {
  readonly version: '1.11.0'
  readonly sha256: '<hex of openapi.yaml>'
}

/** The consumer this module describes: its operations and its vocabulary. */
export declare const CONSUMER: 'admin'

/** Every capability some admin operation requires, sorted. */
export declare const CAPABILITIES: readonly ['merchants:read', 'merchants:write' /* … */]
export type Capability = (typeof CAPABILITIES)[number]

/** What the contract demands of each admin operation. */
export declare const OPERATIONS: {
  readonly listMerchants: {
    readonly capabilities: readonly ['merchants:read']
    readonly idempotent: false
  }
  readonly createMerchant: {
    readonly capabilities: readonly ['merchants:write']
    readonly idempotent: false
  }
  readonly publishMerchantConfiguration: {
    readonly capabilities: readonly ['configuration:write']
    readonly idempotent: true
  }
  // … every operation whose tag is `admin`
}
export type OperationId = keyof typeof OPERATIONS
```

Reglas de la forma:

- **Sólo el consumidor `admin`** en esta feature; `CONSUMER` lo dice. El portal, cuando exista, pide
  su módulo con `CONSUMER: 'portal'` en otro archivo (`capabilities.portal.*`), no mezcla.
- `capabilities` de cada operación es **el `x-required-capabilities` tal cual**, en el orden del
  contrato. `idempotent` es `true` si la operación declara `x-idempotency`.
- `CAPABILITIES` es la unión **ordenada y sin repetidos** de todas; es el vocabulario contra el que
  `operation()` compila y contra el que la sesión falsa arma sus papeles.
- Los literales viajan como literales (`as const` del lado `.js`, `readonly [...]` del lado
  `.d.ts`): es lo que hace que un typo **no compile**.

## `capabilities.js`

El mismo contenido como valores, para quien lo lea al correr (la sesión falsa, `conformity`):

```js
export const CONTRACT = { version: '1.11.0', sha256: '…' }
export const CONSUMER = 'admin'
export const CAPABILITIES = ['merchants:read', 'merchants:write' /* … */]
export const OPERATIONS = { listMerchants: { capabilities: ['merchants:read'], idempotent: false } /* … */ }
```

## `identity.json`

```json
{
  "$comment": "GENERATED by <script> — DO NOT EDIT BY HAND.",
  "version": "1.11.0",
  "sha256": "<hex of openapi.yaml>",
  "backendCommit": "<sha of OPE-Backend at sync time, when known>"
}
```

## Lo que `conformity` verifica

1. `sha256(contracts/ope/openapi.yaml) === identity.sha256 === CONTRACT.sha256`. Si no: «el
   contrato y el módulo se despegaron: corré `npm run contract:sync`».
2. `CONTRACT.version === info.version` del bundle.
3. Cada clave de `OPERATIONS` existe en `operations` de `api.d.ts`; cada operación con tag `admin`
   del bundle existe en `OPERATIONS`. Una de más o de menos falla nombrándola.
4. `CAPABILITIES` es exactamente la unión de las capacidades de `OPERATIONS`, ordenada.
5. **Cuántas operaciones y capacidades revisó**, en el informe; con cero, falla (`TAN-6`, regla 4).

## Lo que `@ope/core` publica para tiparlo

```ts
// packages/core/src/data/contract.ts
export type ContractModule<Ops extends Record<string, OperationRequirement>> = {
  readonly CONTRACT: { readonly version: string; readonly sha256: string }
  readonly CONSUMER: string
  readonly CAPABILITIES: readonly string[]
  readonly OPERATIONS: Ops
}
export type OperationRequirement = {
  readonly capabilities: readonly string[]
  readonly idempotent: boolean
}
```

La aplicación lo cierra con su módulo: `import * as admin from '../../../contracts/ope/capabilities'`,
y `opeOperation<Id extends keyof typeof admin.OPERATIONS>` toma de ahí las capacidades. El tipo
**no sabe qué es `merchants:read`** (principio III): sabe que es una de las que el módulo lista.
